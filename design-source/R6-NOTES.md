# Madonna R6 — signature and mobile composition

The customer hero now centers the actual interwoven Madonna monogram. Its silhouette was traced from the published transparent logo: one connected component and six preserved holes. The 4-unit-tall mark has a true 0.23-unit depth, rounded bevels, ceramic front and pale champagne side material. GLB is 117,920 bytes / 5,900 triangles versus the former 1.02 MB / 49,784-triangle orchid. Source trace, mesh scripts, studio-render scripts, an optional Blender project generator, and geometry validation are preserved in `signature/`. Blender was unavailable here; faithful mesh extrusion and Mitsuba path tracing produced the asset and fallback. The exact lossless 1400px fallback has cleaned transparency.

The mobile hero uses separate grid rows for header, captions, sculpture, stable booking CTA and motion/progress control. Side slogans and the background word are removed from the hero. A scroll-driven arc and moving grazing light reveal the monogram's depth without a render loop for decorative idle animation. The camera fits the model to its own viewport. Reduced-motion and short-height layouts use normal flow. Scroll phase uses the stable pin height, avoiding mobile address-bar height changes. API and administration links remain separated.

Mobile service photography, caption, tabs and booking actions occupy separate rows. The selected photo has subtle adjacent slivers, working arrows, swipe and a horizontal category strip. Duplicate dots and repeated mobile heading copy are hidden. Texture crop respects the configured image focal point. Rendering stops when still and offscreen; interactive frames follow rAF. Adaptive DPR learns faster refresh intervals to protect high-refresh interaction when available, without promising a hardware-independent FPS.

Booking on mobile has a 64px header, one scrolling content region and an external persistent action dock. The final dock submits the real associated form and retains native validation. The service name has more space; date choices scroll horizontally. The summary uses the full width and the dark brand palette. No second 3D scene is mounted for mobile booking. Busy guards, Radix focus restoration, receipt handling, shared bookings, authorization, PWA scope and private deployment access are preserved.

Original service photographs remain pending from the user; the existing photographs remain labelled representative. No new model-generated service photography was substituted.

Validation: TypeScript, production build, existing booking/PWA/SSR checks, faithful mesh/size/depth validation and projection checks throughout the scroll arc at five narrow/wide viewport sizes. The source audit corrected mobile summary contrast and live reduced-motion accessibility. No browser or physical-device FPS measurement was performed; screenshot evidence supplied by the user guided the mobile redesign.
